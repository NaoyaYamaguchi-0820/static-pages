Tailwind CSS の特徴

👍 長所

  • ・既定の見た目が無いので、デザインカンプ通りに作れる（打ち消しCSSが不要）
  • ・クラス名を考える時間がゼロになる。命名規則の議論が消える
  • ・HTMLを見れば見た目が分かり、削除しても他画面が壊れない
  • ・md: hover: dark: のバリアントで状態やレスポンシブを1行で表現
  • ・ビルド時に未使用クラスが消えるため、最終的なCSSは数KBで済む

⚠️ 短所・注意点

  • ・class属性が非常に長くなる。HTMLの可読性は確実に下がる
  • ・コンポーネントが一切付属しない。モーダルやタブは自分で作る（このページは <dialog> を使用）
  • ・クラス語彙を覚えるまでの立ち上がりに時間がかかる
  • ・繰り返しは @apply やコンポーネント化で吸収する設計判断が必要
  • ・Play CDNは開発用。本番はビルド必須（v4は @import "tailwindcss" のCSS設定方式）

向いているケース

デザイナーが作ったカンプを忠実に再現したいプロダクト、長期運用でCSSの肥大化を避けたいチーム、 React/Vue などコンポーネント単位で開発する環境。逆に「HTMLだけ書いて整えたい」用途には向きません。

CDNの書き方（開発用）

<script src="https://cdn.tailwindcss.com"></script>
<script>tailwind.config = { darkMode:'class', theme:{ extend:{ colors:{ /* ... */ } } } }</script>
